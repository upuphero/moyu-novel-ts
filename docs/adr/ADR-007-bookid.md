# ADR-007：路径稳定性与同文件识别的 bookId 取舍；文件移动后的行为

> 状态：接受（Phase 2 关闭）· 2026-08-13
> 关联：DEVELOPMENT_PLAN.md §9 / Phase 2（P2-01）

## 背景

需要为每本书生成稳定 ID，以隔离同名文件的状态、支撑语义进度。候选：路径哈希 / 内容哈希 / 文件名。

| 候选 | 优点 | 缺点 |
| --- | --- | --- |
| 路径哈希 | 计算快（O(1)）；路径唯一则状态隔离 | 移动/重命名后 ID 变化，进度丢失 |
| 内容哈希 | 移动/重命名保留 ID | 大文件全文哈希成本高；任何修改（哪怕改一个字）都失效 |
| 文件名 | 简单 | 同名冲突（正是要解决的问题） |

## 决策

1. **bookId = `book:1:<sha256(normalizedPath) 前 16 hex>`**（算法版本化，`BOOK_ID_VERSION = 1`）。
2. **路径规范化**：仅统一分隔符（`\` → `/`），**不做大小写折叠**——Windows 用户手动改盘符/
   大小写会导致 ID 变化，但在 Linux 上避免不同文件（仅大小写不同）碰撞；跨平台一致性优先。
3. **文件移动/重命名后的行为**：
   - bookId 变化 → 旧进度不自动关联（`moyuNovel.progress.<旧bookId>` 保留但不可达）。
   - `moyuNovel.lastOpened` 保存 fullPath：书架按 fullPath 找不到该书时，恢复退化为章节开头，
     不崩溃、不报错。
   - 不实现自动重命名映射（成本高、易错）；文档说明用户可通过"重新打开章节"重建进度。
4. **ID 可安全用作状态 key**：bookId 只含 `book:1:<hex>`，无原始路径明文。
5. **版本升级**：算法/版本变化时必须递增 `BOOK_ID_VERSION` 并提供失效或迁移路径。

## 后果

- 正面：同名不同路径状态隔离（P2-01 验收）；ID 稳定可测；key 安全。
- 负面/风险：文件移动丢失进度是已知限制，README 明示；`lastOpened.fullPath` 作为人工定位线索保留。

## 验收

- [x] 单测：同一路径稳定、不同路径不同、分隔符归一、版本前缀、无路径明文。
- [x] 集成测试：Book 两次构造 bookId 一致；同名不同路径不同。
